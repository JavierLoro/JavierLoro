MCP · PERSISTENT KNOWLEDGE

Alexandrie — Persistent knowledge through MCP ↗

I use Alexandrie as my self-hosted knowledge base and built an MCP layer on top so Claude, coding agents and other clients can access the same persistent information across environments and conversations.

Uso Alexandrie como base de conocimiento autohospedada y construí una capa MCP para que Claude, agentes de programación y otros clientes accedan a la misma información persistente entre entornos y conversaciones.

MCP TypeScript Go Streamable HTTP Docker
Claude / agents → Custom MCP → Persistent knowledge
Engineering details Detalles técnicos

I extended an existing self-hosted application with an MCP server exposing its knowledge model through semantic operations.

  • Tools for navigating, searching, reading and modifying documents.
  • Outline and section-level reads to avoid loading full documents unnecessarily.
  • Focused tool responses to reduce context usage.
  • Streamable HTTP access with authentication and token handling.
  • MCP rendering kept synchronized with the application's Markdown renderer.
  • Deployment and operation on my own infrastructure.

The goal was not to add a chat to a wiki, but to turn persistent knowledge into a reusable capability for different agents and environments.

Extendí una aplicación autohospedada existente con un servidor MCP que expone su modelo de conocimiento mediante operaciones semánticas.

  • Herramientas para navegar, buscar, leer y modificar documentos.
  • Lecturas por esquema y sección para evitar cargar documentos completos innecesariamente.
  • Respuestas de herramientas ajustadas para reducir contexto.
  • Acceso Streamable HTTP con autenticación y gestión de tokens.
  • Renderizado MCP sincronizado con el renderer Markdown de la aplicación.
  • Despliegue y operación en mi propia infraestructura.

El objetivo no era añadir un chat a una wiki, sino convertir conocimiento persistente en una capacidad reutilizable para distintos agentes y entornos.

PRIVATE · ONGOING · AGENT ORCHESTRATION

Codex Projects Replica

A private engineering project exploring persistent coordination, bounded context and verifiable workflows for coding agents.

Un proyecto privado de ingeniería que explora coordinación persistente, contexto acotado y flujos verificables para agentes de programación.

Agent orchestration Persistent state Independent verification Bounded context MCP
User → Coordinator → Orchestrator → Workers / Verifier → Control Plane
Architecture and principles Arquitectura y principios

The project separates conversation, execution and durable project state.

Persistent coordination

The Coordinator owns continuity and delegates bounded goals to a temporary Orchestrator.

Bounded context

Agents receive only the context required for the current task rather than the full project history.

Independent verification

A separate verifier checks repository state, expected files, tests, regressions and completion evidence, returning explicit VERIFIED / FAILED / BLOCKED outcomes.

Persistent project memory

Tasks, decisions, receipts, dependencies and verification evidence survive individual sessions.

LLMs reason. Code verifies. Persistent state provides continuity.

El proyecto separa conversación, ejecución y estado durable del proyecto.

Coordinación persistente

El Coordinator mantiene la continuidad y delega objetivos acotados a un Orchestrator temporal.

Contexto acotado

Los agentes reciben únicamente el contexto necesario para la tarea actual, no todo el historial del proyecto.

Verificación independiente

Un verificador separado comprueba estado del repositorio, archivos esperados, tests, regresiones y evidencia de finalización, devolviendo resultados explícitos VERIFIED / FAILED / BLOCKED.

Memoria persistente

Tareas, decisiones, receipts, dependencias y evidencia de verificación sobreviven a las sesiones individuales.

Los LLM razonan. El código verifica. El estado persistente aporta continuidad.
