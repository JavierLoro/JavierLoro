MCP · PERSISTENT KNOWLEDGE

Alexandrie — Persistent knowledge through MCP

ProblemProblema

Useful project knowledge gets fragmented between AI conversations and environments.El conocimiento útil de un proyecto se fragmenta entre conversaciones y entornos de IA.

What I builtQué construí

An MCP server over my Alexandrie fork with semantic read/write tools, Streamable HTTP and context-efficient responses.Un servidor MCP sobre mi fork de Alexandrie con herramientas semánticas de lectura/escritura, Streamable HTTP y respuestas eficientes en contexto.

ResultResultado

The same persistent knowledge can be reused by multiple MCP clients without copying full documents into every session.El mismo conocimiento persistente puede reutilizarse desde distintos clientes MCP sin copiar documentos completos en cada sesión.

Role / scopeRol / alcance

Fork maintainer · MCP extension, HTML documents, backend hardening and deployment.Mantenimiento del fork · extensión MCP, documentos HTML, hardening del backend y despliegue.

MCPTypeScriptGoStreamable HTTPDocker
View codeVer código ↗
Explore engineering detailsExplorar detalles técnicos
  • Navigation, search, outline, section-level reads and write operations designed as semantic MCP tools.
  • Token funnel: agents can inspect an outline or one section instead of loading an entire document.
  • Write responses avoid echoing unnecessary content.
  • The MCP Markdown pipeline is regenerated from the application's renderer so both outputs stay aligned.
  • Remote access uses Streamable HTTP, authentication and restart-free token rotation.

The interesting part was turning persistent knowledge into a reusable capability for agents, not adding another chat interface.

  • Navegación, búsqueda, esquemas, lecturas por sección y escritura diseñadas como herramientas MCP semánticas.
  • Token funnel: el agente puede inspeccionar un esquema o una sección sin cargar el documento completo.
  • Las respuestas de escritura evitan devolver contenido innecesario.
  • El pipeline Markdown de MCP se regenera desde el renderer principal para mantener ambos resultados alineados.
  • El acceso remoto usa Streamable HTTP, autenticación y rotación de token sin reinicio.

La parte interesante era convertir el conocimiento persistente en una capacidad reutilizable para agentes, no añadir otra interfaz de chat.

Explore engineering detailsExplorar detalles técnicos
  • Domain operations instead of visual UI automation.
  • Agent proposals remain different from authoritative human decisions.
  • Resident Agent is read-only; Import Agent is ephemeral and cannot confirm its own output.
  • Repository exploration has explicit limits on calls, files, bytes, tokens and estimated cost.
  • Imports separate facts, inferences, unknowns and provenance before a human confirms them.

Agents come and go. The workspace remembers.

  • Operaciones del dominio en lugar de automatización visual de la interfaz.
  • Las propuestas del agente siguen separadas de las decisiones humanas autoritativas.
  • Resident Agent es de solo lectura; Import Agent es efímero y no puede confirmar su propio resultado.
  • La exploración de repositorios tiene límites explícitos de llamadas, archivos, bytes, tokens y coste estimado.
  • Las importaciones separan hechos, inferencias, incógnitas y procedencia antes de la confirmación humana.

Los agentes vienen y van. El workspace recuerda.
